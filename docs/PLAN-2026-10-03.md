## Shared contract
- `oracle_searcher/schema.py`: the SQLite schema (tables `cards`, `card_faces`, `meta`) and its conventions. Neither lane changes it without saying so in its report; if a lane needs a column, it adds it in its own commit, explains why, and the merge reconciles.
- Real fixtures, cut from the 2026-10-03 bulk files (`~/.cache/tcg-oracle-searcher/` has the full files):
  - `tests/fixtures/oracle_cards_sample.jsonl`: 58 cards covering every layout, the Jace cards, Ral, Valki, previews, game changers, split, adventure, MDFC, tokens, an emblem, an art card;
  - `tests/fixtures/oracle_tags_sample.jsonl`: the 386 tags that touch them, plus ancestors;
  - `tests/fixtures/purroxy_queries.txt`: 39 real queries Purroxy sends.
- **Search API** (orange builds it, grey's Lambda handler calls it):
  ```python
  search(conn, q: str, order: str = "edhrec", dir: str = "auto", page: int = 1, page_size: int = 175) -> SearchResult
  # SearchResult: data (list of card dicts from card_json), has_more (bool), total_cards (int)
  # raises Unsupported(reason) when the query can't be answered exactly; never a partial or guessed answer
  ```

## 🟢 Green: importer (`oracle_searcher/importer.py`)
- `build(cards_path, tags_path, out_path) -> dict` (stats): streams gzipped or plain JSONL and writes the SQLite file per `schema.py`. It writes to `out_path + ".tmp"` and renames at the end, so a failed build never leaves a half file.
- **Reuse Sylvan's `api/card_processing.py`** (type parsing, rarity, mana dict, devotion, is: tags) rather than rewriting it. Read how Sylvan's import fills each column (`api/card_processing.py`, `api/db/`) and match it, with the multi-face rules from `schema.py`.
- **`is_extra`:** decide which layouts and types Scryfall's search hides by default. Check it against Scryfall itself (see "Scryfall calls" below), and record the evidence in a test docstring.
- **`card_json`:** the Scryfall object trimmed of fields no caller needs (multiverse/mtgo/arena/tcgplayer/cardmarket ids, `*_uri` fields except `image_uris`, `purchase_uris` and `scryfall_uri`). Keep `card_faces`, `all_parts`, `prices`, `legalities`, `image_uris` and `edhrec_rank`. Report the size before and after.
- **Oracle tags:** `card_oracle_tags` holds each tagged card's tag slugs plus every ancestor's slug (`parent_ids`, transitively).
- **`check(db_path) -> list[str]`:** problems found (empty means good). Card count over 30,000 for a full file, known cards present, every multi-face card has faces. It runs before a build is published.
- **CLI:** `python -m oracle_searcher.importer --cards X --tags Y --out Z`.
- **Tests (fixtures only):**
  - Jace, Vryn's Prodigy has Creature and Planeswalker in `card_types`, both faces' text in `oracle_text`, and face 2 with loyalty 5;
  - Valki (MDFC), Heaven // Earth (split) and Gollum (adventure) map correctly;
  - colour, identity and produced masks;
  - legalities;
  - the preview card is present;
  - `game_changer`;
  - tag ancestors;
  - `is_extra`;
  - the atomic rename (a failed build leaves no file);
  - `check` failures.
- **Then a full-file build:** report the time, peak memory, the SQLite size, and the gzipped size.

## 🟠 Orange: compiler and search (`oracle_searcher/sqlite_compiler.py`, `oracle_searcher/search.py`)
- **Parse with Sylvan's hand parser** (`api.parsing.parse_scryfall_query`), then compile its tree to a parameterised SQLite `WHERE` clause over `schema.py`. Write it as a separate compiler that walks the nodes; Sylvan's `to_sql` methods (PostgreSQL) are only a reference.
- **Any node, attribute or operator not handled exactly raises `Unsupported`.** Cover Purroxy's corpus (`tests/fixtures/purroxy_queries.txt`) first, then the rest in order of use.
- **Multi-face rules** from `schema.py`; numeric attributes check `card_faces` with `EXISTS`.
- **Regex** through a registered `REGEXP` function (Python `re`, with Sylvan's regex budget).
- **Colour logic:** colour and identity comparisons (`c:`, `id<=`, `c>=`, `c=`, colourless, multicolour) on the masks, matching Scryfall.
- **Hide `is_extra` rows** unless the query asks for them (as Scryfall does: `include:extras`, `t:token`, and so on; confirm with Scryfall).
- **Ordering:** `edhrec` (rank ascending, unranked last), `released`, `name`, `cmc`, `usd`, with `dir=auto|asc|desc` exactly as Scryfall's docs define each default. Paging: `page_size` 175, `has_more`, `total_cards`.
- **Tests:** build a small database in each test from the fixture cards. Until green's importer is merged, insert rows with a test helper that fills only the columns a test needs; grey switches these to the real importer at merge.
  - every query in Purroxy's corpus compiles, or raises `Unsupported` with a reason;
  - each operator family;
  - multi-face matches (`o:` text found only on a back face, `t:planeswalker` finding Jace, Vryn's Prodigy, loyalty on a face);
  - ordering and paging;
  - extras hidden.

## 🟣 Purple: parity fixes (next lane)
1. **Reminder text.** Scryfall's `o:` ignores reminder text (the parenthesised part); ours matches it. Example: Barren Moor matches `o:draw` through its cycling reminder. Fix it the way Scryfall does, with real cards and saved Scryfall answers as evidence.
2. **`t:token` finds nothing.** The compiler sends unknown type words to subtypes; check how the importer stores "Token" and make `t:` match Scryfall for supertypes and words such as token, emblem, plane, scheme, vanguard.
3. **`is:commander`.** Scryfall uses the front face (Westvale Abbey // Ormendahl and Invasion of Ikoria are not commanders) and counts `*` toughness (Ashaya, Daxos, Lumra are). Compute it at import from Scryfall's rule, or fix the rewrite, whichever matches Scryfall exactly.
4. **Default-hidden cards.** Scryfall's default search shows 33,649 cards (`date>=1993`, saved in `tests/fixtures/scryfall/broad_default.json`); ours shows 34,605 non-extras. The extra cards are mostly `set_type` alchemy (digital-only Arena cards, often legal nowhere) and funny (Un-set and playtest cards), but no single obvious rule fits: "legal in no format" hides 30 of our 722 elves where Scryfall hides 24. Find Scryfall's real rule with counting queries (for example `t:elf`, `t:elf st:alchemy`, `t:elf st:funny`, `t:elf is:digital`, `t:elf -is:playtest`, `include:extras`) and set `is_extra`, or a new flag, to match.
5. **Tests on the real importer.** Switch `tests/helpers.py` from hand-built rows to rows built by the importer from the fixtures, so the compiler is tested on what it will really read.
6. **Commit the harness.** Make `scripts/parity.py` a proper script (arguments, a summary line with how many queries are within 1% on totals and at least 0.9 on the top 20), and add a queries file with Purroxy's real composite forms (identity and legality suffixes).
7. **Acceptance:** every corpus query within 1% of Scryfall's total and at least 0.9 overlap in the top 20, or the gap explained in the plan with evidence.

## 🔵 Teal: every `is:` tag (owner, 2026-10-03: "fetchland" will come up in natural-language search)
Sylvan answers some `is:` tags from the card row (its BOOLEAN_IS_TAGS, ported by green), expands others in `api/parsing/rewrite.py` (for example `is:commander`), fills its LAND_IS_TAGS and CARD_IS_TAGS (fetchland, shockland, ..., commander, vanilla, reserved, outlaw, party, bear) by asking Scryfall `is:<tag>` one tag at a time from an admin action, and doesn't support `historic`, `permanent`, `spell`, `unique`, `old`, `new`, `default`.
1. **Inventory every `is:` (and `has:`) value** on Scryfall's syntax page (scryfall.com/docs/syntax). Mark each: answered from the card row by a rule; swept from Scryfall; or meaningless for one-row-per-card data (printing-level tags such as `foil`, `promo`; these raise `Unsupported`). Save the inventory in `docs/is-tags.md`.
2. **Sweep:** `oracle_searcher/is_tag_sweep.py`.
   - `sweep(tags) -> dict[tag, list[oracle_id]]` asks `https://api.scryfall.com/cards/search?q=is:<tag>&unique=cards`, following `next_page`, at most 2 requests a second (Scryfall's limit for search; use 1 a second to be safe). A 429 stops the sweep and keeps the previous result for the tags not yet done.
   - It writes a JSON file `{"swept_at", "tags": {tag: [oracle_ids]}}`.
   - `apply_sweep(conn, sweep_path)` adds each tag to `card_is_tags` for its cards.
   - This is a separate step from `importer.build`: the import stays network-free, and the Lambda importer runs build, then apply, then check.
   - Tags too big to sweep cheaply (thousands of cards) are rules instead, if a rule matches Scryfall's count exactly. Prove it with a saved count.
3. **The compiler** answers `is:<tag>` from `card_is_tags` for every swept or ruled tag, and raises `Unsupported` for printing-level ones.
4. **Tests:** sweep paging and 429 handling against saved responses (never live); `apply_sweep`; each rule-derived tag against a saved Scryfall count; and `is:fetchland`, `is:shockland`, `is:commander` and `is:historic` end to end on fixtures.
5. **A live sweep** of every swept tag into `.scratch/is_tags.json`: report how many requests and how long it took. Then a parity check of each tag's count against Scryfall's `total_cards`.

Don't edit `importer.py`'s internals or `sqlite_compiler.py` beyond the `is:` handling (the purple lane is changing them in parallel). Put new code in new modules and keep the hooks small.
